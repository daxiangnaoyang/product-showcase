# 产品展示输出模板

所有方括号字段都必须从产品事实卡取值。没有证据时写“待补充”，不要用示例值替代。

## 1. 推荐语

结构：场景/痛点钩子 → 已确认卖点 → 用户利益 → 用户指定的行动语。

模板：

> [什么人在什么场景遇到什么问题]？[产品名]的[卖点 1]，可以[已确认的使用利益]；再加上[卖点 2]，适合[目标人群/场景]。 [按用户要求写行动语；没有要求时不擅自承诺成交或发布。]

检查：

- 1—3 句，先讲场景再讲卖点。
- 不把“可能/推测/宣传口号”写成确定功效。
- 价格、优惠、认证、排行和对比只在事实卡已有证据时出现。

## 2. 朋友圈短文

默认 80—200 字；用户指定平台或长度时优先服从。

~~~text
[开头：一个具体痛点、场景或反常识观察]

[产品名]解决的是[已确认的问题]。
它的[卖点 1]意味着[生活化利益]，[卖点 2]适合[场景]。
如果你也有[目标人群的处境]，可以重点看[最相关卖点]。

[用户指定的行动语；没有授权时不代发、不代聊、不写虚假的优惠或稀缺性。]
~~~

需要 A/B 版本时，只改变切入场景或语气；事实、卖点顺序和不可用表达保持一致。

## 3. 电商卖点图解卡

先逐张完成图解卡，再调用图像生成/编辑能力：

| 字段 | 内容 |
|---|---|
| 图号/用途 |  |
| 核心卖点 | 只放一个主要卖点 |
| 事实依据 | 用户原文或可见画面 |
| 产品参考图 | P01/P02/... |
| 必须保留 | 轮廓、颜色、结构、Logo、包装文字 |
| 画面动作/细节 | 让卖点能被看见 |
| 允许出现的文字 | 标题、数字、单位、利益短句 |
| 比例 | 3:4 / 4:5 / 9:16 |
| 风格 | 产品调性、平台和用户指定风格 |
| QA | 身份 / 文字 / 数字 / 构图 / 状态 |

通用 Prompt 结构：

~~~text
以产品参考图 [P 编号] 为唯一产品身份参考，保留产品的轮廓、颜色、结构、Logo 位置和可读包装文字。
将画面重构为 [比例] 的电商卖点图解，主题只讲“[一个卖点]”。
画面主体：[产品主体与可见细节]。
画面关系：[使用动作/局部特写/前后状态/场景关系]。
允许出现的文字只有：“[标题]”“[数字/单位，如无则删除]”“[利益短句]”。
不得新增价格、参数、功效、认证、人物、竞品、Logo 或未提供的标签。
生成后逐字检查中文、数字、单位与产品身份；不符合就标记为未通过，不交付。
~~~

用户未指定风格时，优先可读、可比、可快速理解的版式；不要把深色大片风、浅色卡片、引导线或某个品牌风格设成所有产品的硬规则。

## 4. 15 秒视频分镜

默认 9:16、精确 15 秒：

| 镜号 | 时间 | 画面 | 产品素材 | 口播 | 字幕 | 动作/转场 | 事实依据 |
|---|---:|---|---|---|---|---|---|
| 1 | 0—2s | 产品主体或痛点钩子 | P01 |  |  |  |  |
| 2 | 2—5s | 使用处境 | P01/场景图 |  |  |  |  |
| 3 | 5—8s | 卖点 1 的可见演示 | P02 |  |  |  |  |
| 4 | 8—10s | 卖点 2 的可见演示 | P03 |  |  |  |  |
| 5 | 10—13s | 已确认的使用利益/结果 | 场景图或编辑画面 |  |  |  |  |
| 6 | 13—15s | 产品名与收束 | 产品主图 |  |  |  |  |

规则：

- 15 秒内只保留最高优先级的 2—3 个卖点。
- 每句字幕短到能在手机上读完；口播和字幕不必逐字相同，但不能互相矛盾。
- 没有产品图时只能交付概念分镜；不能把文生视频描述为真实产品展示。
- 有视频生成能力且用户需要成片时，再把分镜转成视频任务；输出文件须单独记录路径和状态。
